## 实现差异与边界

- 任务书给出的目录与实施提示不是唯一实现方式：本项目表单在 utils/form.py；工资公式集中于模型 save，而不是仅在视图 commit=False 后计算。
- 新头像通过明确关联的 UserAvatar 保存和读取，Employee.avatar 保留历史兼容。新增员工不会自动建登录账号，需先确认关联。
- AJAX 校验错误分支不刷新页面；成功分支回任务第一页以保持总数/分页/排序正确。
- 当前考勤单状态设计先判断迟到，再判断早退；同时迟到早退会显示迟到。
- 模型 full_clean 与普通 save 是两回事；直接 SQL/批量 update 不会自动走全部表单规则。
- CLI 开发默认 DEBUG=1，不代表生产合格。生产环境变量、TLS/代理、登录限速、口令轮换等需另行审核。
- 默认测试口令按需求保留；本次不会修改真实数据库密码或账号资料。部署检查使用的是临时模拟变量，并未变更用户生产配置。
- 没有制造 Git 历史；没有在用户浏览器逐页点击或导出包含个人资料的截图。


## 2026-11-06 后续功能与交付验收

### 员工与账号

- 新建员工页增加“同时开通登录账号”：具备开通权限时默认勾选，需填写并确认初始密码；可取消勾选只保存档案。
- 新账号固定为普通员工，档案、账号、角色关系在同一个事务中保存；越权参数、重名、密码错误、身份冲突或中途保存失败均不能留下半成品。
- 无开通权限时禁用选项并说明原因，部门范围限制保持不变；已有账号与密码不重置。
- 新注册的登录名及注册姓名均不能重名，历史空姓名的账号会核对关联员工；业务注册页与 Django 后台复用同一检查。员工档案可登记实际同名人，但不能重复开通同名账号。
- 系统用户按实际授权优先排序，在 SQL 中排序后分页。共享权限不重复计数，同级同权限数量按 ID 稳定排序；员工职位排序仍独立生效。
